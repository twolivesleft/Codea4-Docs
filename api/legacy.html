Legacy Compatibility¶

The modern renderer supplies compatibility globals from codea/legacy.lua so older projects can migrate gradually. These are migration helpers, not the preferred API for new code. The wrappers do not restore the legacy renderer or all of its behavior. Use the corresponding modern modules when updating a project.

Migrating a project¶

Replace drawing-state globals with style and transforms with matrix. Use image.read and image.save for assets, storage for persistent data, and time and touch for current frame state. Keep paired push/pop calls balanced. Test text alignment and image filtering: the compatibility layer translates old conventions rather than simply renaming every call.

The old physics global is a compatibility facade over physics2d. It translates numeric body/joint constants and legacy collision callbacks; new projects should use the world, body, collider and joint APIs directly. CAMERA and CAMERA_DEPTH follow sensor images (or a placeholder until a frame arrives). cameraSource reads or changes the sensor camera selection.

Deprecated since version 4.0: Use storage.global:namespace("__legacy.local." .. asset.name):get(tostring(key), defaultValue).

listProjectData()¶

Returns sorted keys from storage.project beginning with __legacy.project., with that prefix removed. Other modern storage keys are excluded.

Deprecated since version 4.0: Use storage.project:keys() and filter the legacy prefix when migrating existing data.

clearProjectData()¶

Deletes only storage.project keys beginning with __legacy.project.. Other modern project data is retained.

Deprecated since version 4.0: Use storage.project:set(key, nil) for each legacy-prefixed key. Clearing the entire modern store would also delete unrelated data.
